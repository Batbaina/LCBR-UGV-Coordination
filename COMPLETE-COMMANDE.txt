================================================================================
1. BUILD THE ALGORITHM
================================================================================

From the repository root:

cd LCBR-UGV-Coordination/algorithm

mkdir -p build
cd build

cmake -DCMAKE_BUILD_TYPE=Release ..

make -j$(nproc)

ctest --output-on-failure

cd ..

The executable should be:

algorithm/build/ugv_coordination


================================================================================
2. CHECK THE EXECUTABLE
================================================================================

./build/ugv_coordination --help


================================================================================
3. FULL PIPELINE — CORRIDORS 6 UGV
================================================================================

Go to:

cd LCBR-UGV-Coordination/algorithm

Create the output directory:

mkdir -p runs/full_pipeline/corridors_6ugv


Run the complete pipeline:

./build/ugv_coordination \
  --input experiments/full_pipeline/instances/paper_corridors_6ugv.yaml \
  --output runs/full_pipeline/corridors_6ugv/final_lcbr.yaml \
  --nominal-output runs/full_pipeline/corridors_6ugv/nominal.yaml \
  --mode lcbr \
  --delta_w_steps 10 \
  --timeout 600 \
  --vehicle-config config/vehicle_config.yaml


Pipeline:

Scenario
   |
   v
SHA* nominal trajectory generation
   |
   v
M x Q SHA* trajectory-cost matrix
   |
   v
Hungarian task allocation
   |
   v
nominal.yaml
   |
   v
Conflict detection
   |
   v
LCBR
   |
   v
final_lcbr.yaml


Generated files:

runs/full_pipeline/corridors_6ugv/nominal.yaml

runs/full_pipeline/corridors_6ugv/final_lcbr.yaml

10. COMPARISON PRINCIPLE
================================================================================

For the same selected instance:

                         SAME INSTANCE
                              |
                  +-----------+-----------+
                  |                       |
                  v                       v
               CL-CBS                    LCBR
                  |                       |
        full-horizon replanning     bounded local repair
                                          |
                                          v
                                  full-horizon fallback
                                  when required


The objective is to compare the conflict-resolution mechanisms while keeping
the common planning machinery consistent.

trajectories/dense/agent3_dense.yaml

The reconstruction preserves:

- straight primitives,
- circular turning primitives,
- forward direction,
- reverse direction,
- WAIT actions,
- planner timestamps.


The script also performs the primitive endpoint audit.

================================================================================
20. EXPECTED FINAL GAZEBO RESULT
================================================================================

A successful execution should terminate with:

MULTI-UGV MISSION END | complete=6/6 | failed=0/6


The six UGVs should:

- follow their assigned trajectories,
- execute forward primitives,
- execute reverse primitives,
- respect LCBR WAIT actions,
- preserve temporal coordination,
- avoid static obstacles,
- avoid inter-UGV collisions,
- reach their assigned goals.


================================================================================
21. CHECK GAZEBO REAL-TIME FACTOR
================================================================================

While Gazebo is running:

gz topic -l | grep stats


Then use the world stats topic, for example:

gz topic -e \
  -t /world/paper_corridors_6ugv/stats


Look for:

sim_time
real_time
real_time_factor
step_size


IMPORTANT:

<real_time_factor> in the SDF is a TARGET.

The actual achievable real-time factor depends on:

- CPU,
- Gazebo physics,
- GUI rendering,
- number of obstacles,
- number of UGV models.

22. FAST GAZEBO — HEADLESS TEST

gz sim -r -s \
  install/ugv_gazebo/share/ugv_gazebo/worlds/paper_corridors_6ugv.sdf


NOTE:

-s = server only / no Gazebo GUI.

This can substantially increase the achievable real-time factor because
the 3D scene is no longer rendered.
